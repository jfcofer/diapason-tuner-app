## Goal

Real microphone in and real audio out on Android, through the `T-002a` engine, on the device this
project actually has: the **Redmi 23117RA68G** (Android 16, arm64). It is the "budget Android"
row of `TESTING.md` §7, where the fast path is most likely to be refused, which makes it the most
informative device to start on.

## Context

Read first: `docs/PLATFORM_AUDIO.md` in full. Parent: `T-002`. Depends on `T-002a`.

**Decide the binding first, on evidence, with an ADR.** The two candidates:

- the `oboe` crate: a C++ shim, ships `libc++_shared`, with an OpenSL ES fallback for API 26–27,
  where AAudio is unreliable. Check its maintenance status;
- AAudio directly via the `ndk` crate: pure Rust with no C++, but input presets need API 28+, and
  the pin was `minSdk 26` (`tools/versions.env`); `T-008` raises it to 28.

Measure the same things `T-001a` did: the symbols in the shipped `.so`, size delta, 16 KB
alignment, and that it **links**, not merely compiles. If the evidence says to raise `minSdk`,
that is its own task and its own ADR (`AGENTS.md` §8).

Emulator: fine for the permission and lifecycle rows. **Never** use it for latency or callback
timing; emulated audio says nothing about real devices.

## Acceptance criteria

- [x] ADR for the Android audio binding, with the measurements above
- [x] The Android backend passes the `T-002a` conformance suite (on device, via an integration
      test)
- [x] Duplex: mic in and output out on one stream and one clock, on the Redmi

- [ ] Round-trip latency on the Redmi recorded in the journal. **Closed here: moved to `T-002f`**

## Implementation notes

**Plan, approved by the owner on 2026-10-09:** the binding in `adr/0020` (raw `ndk-sys`, since
`ndk` 0.9's stream is not `Send`), minSdk 28 in `adr/0019`, the session in `adr/0022`. Capabilities
come from a Kotlin channel in `core_platform` and reach Rust as configuration. Latency: the in-app
estimate from AAudio timestamps, cross-checked against OboeTester. Metronome-column lifecycle rows
(FGS, MediaSession, lock screen) need the M4 metronome and move there.

**Part 1 (#11):** backend and on-device conformance. The callback runs inside `assert_no_alloc`;
a device canary proves the trap. On the Redmi: the FAST path, shared not MMAP; 9–16 input
underruns at start-up, then 0; worst release callback 281–571 µs of 20 ms. Journal
`2026-10-09-aaudio-*.md`.

**Part 2a (#13):** the `session` crate, FFI start/stop and snapshots, the permission,
`test-integration-android`. **Deviation:** on denial the tuner opens no stream; a dev-only A4 tone
proves output. AAudio refuses the input without `RECORD_AUDIO` (`-896`, generic), so the permission
Dart holds decides `PermissionDenied`. Journal `2026-10-09-session-supervisor.md`.

**Part 2b-i (#16), capabilities** (`adr/0024`): Pigeon in `core_platform`, `choose_input_preset`
in Rust, the permission told to the session, the preset requested beside the one obtained.
**Deviations:** only the two facts the rule reads cross to Rust; Pigeon output is generated by
`just deps`, not committed. The preset is applied: `dumpsys media.audio_policy` showed
`AUDIO_SOURCE_VOICE_RECOGNITION` (6). Journals `2026-10-09-capabilities.md`, `2026-10-10-device-run.md`.

**Part 2b-ii, stream tuning** (`adr/0025`): the output buffer grows a burst per underrun, as
session policy; a refused Unprocessed falls back to VoiceRecognition; `callbackLoad` against the
burst; `check-android-release` checks the engine links AAudio, no `libc++_shared`, within 4 MB per
ABI. **Deviation: no backlog shedding.** It was built, and failed on the Redmi twice: the raw
counter gap shed ~10k frames/s (2026-10-10); measured from the gap's floor it shed ~34k/s with
~70 input underruns/s, where `main` had 0 on the same day and paths (2026-10-21). Cut, with the
owner's approval; stall recovery waits for a measured stall. Journal `2026-10-21-close-stream-tuning.md`.

**Part 3 moved out (2026-10-21).** This file was at its 150-line budget, and each piece is its own
PR with its own criteria, so they became slices of `T-002`: `T-002d` lifecycle (the microphone
stays open once the tuner listens), `T-002e` the overlay and first golden, `T-002f` latency.

## Verification performed

- **Part 1**, Redmi 23117RA68G (Android 16, API 36), `just test-android-device`:
  `android_conformance` 5/5, debug and `--release`; `android_alloc_canary` exit 134 ("memory
  allocation of 64 bytes failed").
- **Part 2a**, `just test-integration-android` (owner): without the microphone, the output ran and
  the input was refused with `-896`; with it, duplex. The debug allocation trap was armed.
- **Part 2b-i**, Redmi: unprocessed **false**, low latency **true** (native 48 kHz / 256), so
  VoiceRecognition; requested and obtained; denied → `permissionDenied` with the output running.
  Host: `session` 21 tests, including the preset truth table and five permission transitions.
- **Part 2b-ii**, Redmi, 2026-10-21, `just test-android-device`: 6/6 in debug and `--release`,
  including the resize (1920 → 2880 of 4104); canary exit 134; 0 input underruns after warm-up
  (8–16 in the first 2 s, as `main`); worst release callback 414–425 µs. Host: `session` and
  `audio_io` 38 tests.
- **By hand (owner):** wired-headphone plug and unplug rebuilt the stream with no crash; revoking
  the microphone in Settings killed the running app (`T-002d` owns what follows from that).
