## Tried and abandoned

- **`flutter build ipa --no-codesign` as the CI iOS check.** The archive succeeds, then Flutter
  fails the run for lacking a development team. `flutter build ios --release --no-codesign` is the
  right shape for a compile-and-link check (`just build-ios-unsigned`).
- **`taiki-e/install-action` for actionlint.** It is not packaged there, and the binstall fallback
  fails. Installed via actionlint's own download script at the pinned tag instead.
- **The cirruslabs Flutter container for goldens.** The tags stop at 3.44.0. Downgrading Flutter
  to match a container would invert the pin's authority (`adr/0016`).

## Surprises

- **A green local `verify` hid two CI-only failures**, both because the working tree had files a
  clean checkout does not: cargokit's `.dart_tool` and Riverpod's `*.g.dart`. Lesson: validate CI
  changes in a fresh clone, which this session then did.
- **actionlint found a bug nobody had noticed.** `with: { components: rustfmt, clippy }`: the comma
  inside a YAML flow mapping ends the value, so clippy was silently dropped. The rust job passed
  only because `rust-toolchain.toml` also lists clippy.
- **STATE.md was wrong in two places.** It said `verify` ran cargo-deny, which it did not. It said
  "no git remote", when a remote existed and had been pushed to. Both are fixed.
- `TESTING.md` §7 lists five reference-device rows while other docs say "four". The tablet row
  alternates. Left as is; it only matters once more devices exist.
