## Surprises

- **A green build is not proof a crate linked.** The first `oboe` measurement passed while
  `strings <.so> | grep -c oboe` was **0** — the probe was never regenerated into the FRB bindings,
  so the linker discarded oboe entirely. Both backends "passed" a test that had measured nothing.
  Corrected by inspecting the shipped `.so`.
- **My own idempotence check for `just gen` was a false pass.** `gen-frb` and `gen-dart` both
  *failed* when run from the repo root — the FRB config lived in the package, and `build_runner`
  at the workspace root writes nothing. With output redirected, "no diff after regenerating" looked
  like success. Both fixed; the config moved to the repo root, `gen-dart` now runs through melos.
- **`docs/DEVELOPMENT.md` §1 was wrong in four places** on the day after it was written: Flutter
  3.44 (3.47.1 was stable), FRB 2.12 (2.13.0 had shipped), NDK r27 "required for 16 KB" (r28+ does
  it by default), and a Java 21 pin that nothing enforced while every JDK path on this machine led
  to JDK 25 — on which Flutter Android builds fail outright. Fixed, and the pins are now
  machine-checked rather than written down.
- **`docs/PLATFORM_AUDIO.md` §2** told us to make `-Wl,-z,max-page-size=16384` reach the Rust link
  step. On NDK r28+ that flag is no longer load-bearing; alignment is the default. Verified
  empirically (`LOAD align 0x4000`) and the doc corrected.
- **`AGENTS.md` §7 was stale twice** — the Flutter pin and `custom_lint`. Both fixed. It is the
  file every agent loads on every request, so a wrong line there is expensive.
- **`cargo deny` rejects `license = "UNLICENSED"`** — not a valid SPDX expression. Since `adr/0009`
  is still Proposed, the honest fix was to declare no licence and have `deny.toml` ignore private
  crates, rather than invent one.
