# 0024 — Pigeon platform channels; Rust picks the preset; the session is told the permission

**Status:** Accepted · 2026-10-09

## Context

`T-002b` part 2b has to choose the Android input preset. Following `PLATFORM_AUDIO.md` §2, that
means Unprocessed when the device reports both `FEATURE_AUDIO_LOW_LATENCY` and
`PROPERTY_SUPPORT_AUDIO_SOURCE_UNPROCESSED`, and VoiceRecognition otherwise. Both facts come from
Java APIs (`PackageManager`, `AudioManager`), which neither Rust nor Dart can call directly. Until
now the app had no platform channel at all.

On the Redmi, part 2a also found that **a refused microphone does not say why**. AAudio fails to
open the input with `-896` (`AAUDIO_ERROR_INTERNAL`), the same code as any other internal failure.
iOS records silence instead. So the session reported `DeviceUnavailable` for a missing permission,
and the UI offered the wrong recovery.

## Decision

- **Platform channels are generated by Pigeon** (owner's choice, 2026-10-09), declared in
  `packages/<pkg>/pigeons/*.dart`. `core_platform` becomes a Flutter plugin package. It is the
  layer that already owns platform capabilities (`ARCHITECTURE.md` §2), and its Kotlin registers
  like any other plugin's.
  - **Pigeon is pinned exactly** (a dev dependency), because its output changes between versions.
  - **The output is generated, not committed**, like `build_runner`'s: `just gen-dart` (and so
    `just deps`) runs every `pigeons/*.dart`. `*.g.dart` and `*.g.kt` are gitignored, and ktfmt
    skips `*.g.kt` (`adr/0023`).
- **The channel only reports.** `CorePlatformPlugin` reads the Unprocessed property, the
  low-latency and pro-audio features, and the native rate and buffer. Dart maps the answer to
  `core_domain`'s `AudioDeviceCapabilities`. A field the platform does not give is `null`, a failed
  channel is `unknown`, and unknown is never read as supported. iOS reports `unknown` until
  `T-002c`.
- **Rust chooses the preset**, in `diapason_session::choose_input_preset`. It is policy, it is
  tested on any host, and it sits beside the backend choice (`session/src/platform.rs`). Only the
  two facts the rule reads cross the bridge, given to `AudioSession::spawn`. AAudio picks the
  native rate and burst itself, so those stay in Dart, for the diagnostics.
- **The session is told the microphone permission** (`MicrophoneAccess`: unknown, granted,
  denied) through `set_microphone_access`. Dart sends it whenever it reads or requests the
  permission.
  - **Denied:** the supervisor never asks the platform for the microphone. The output runs, and
    while the microphone is wanted the input fault is `PermissionDenied`. That fault is derived
    from the two facts, not stored, so no order of calls can lose it (review, 2026-10-09).
  - **A new grant** retries a microphone that failed, on the next tick, with desired state
    replayed. Under an unknown permission, a refusal was the likeliest cause. **Repeating a grant
    is not a new fact**, so it retries nothing and cannot loop.
  - **Granted, but the open still fails:** the failure is the device's (`DeviceUnavailable`).
  - **Unknown:** keeps the old behaviour, so a caller that never reports it loses nothing.
- **The backend reports the preset requested as well as the one obtained**
  (`BackendReport::requested_input_preset`). A mismatch is visible in a support report.

## Consequences

**Good.**
- The preset rule is one pure function with a truth-table test.
- A refused microphone is reported as what it is, on both platforms, and the platform is never
  asked for a microphone the app may not use.
- One typed channel mechanism serves what comes next: lifecycle, audio focus, and the iOS side.

**Bad.**
- `core_platform` now has an Android module to maintain, which follows Flutter's plugin template.
- A clean checkout needs `just deps` before the Android build has its Kotlin bindings. That is
  already true of every `*.g.dart` (STATE.md, Traps).
- Rust trusts Dart's account of the permission. If Dart says granted when it is not, Android
  reports `-896` as `DeviceUnavailable`, as before.

**Rejected.**
- **A hand-written `MethodChannel`:** untyped maps at the boundary, the cost of which grows with
  every call added.
- **JNI from Rust** (`jni` and `ndk-context`): a second binding layer, plus a JVM attach on the
  session thread, to read five properties.
- **Choosing the preset in Dart:** that splits audio policy between two languages
  (`AGENTS.md` §5: business rules live in `session`, `engine` and `dsp`).
- **Committing Pigeon's output**, as frb's is: frb's needs its own codegen binary, while Pigeon
  runs anywhere `pub get` has run, like `build_runner`.
